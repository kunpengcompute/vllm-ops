# OpenVLA 图片前处理加速 — 最终技术报告

> 版本: Final Edition
> 日期: 2026-07-30
> 平台: Huawei Kunpeng 920 (aarch64, 384 线程, NEON + SVE2) / openEuler 24.03 / GCC 12.3.1

---

## 1. 摘要

将 OpenVLA 图片前处理管线（bicubic resize + DINOv2/SigLIP 双路归一化）从 Python (PIL+NumPy) 迁移至 ARM NEON C++ 多核实现。单图延迟从 15.5ms 降至 0.41ms，加速 **37.8×**。与 Pillow BICUBIC 完全兼容（max_err ≤ 1 pixel uint8）。

## 6. 加速技术逐项分析

### 6.1 Resize 加速 (12.3ms → 0.70ms, 17.5×)

| 技术点 | 机制 | 收益 |
|--------|------|------|
| **OMP 多线程** | `#pragma omp parallel for schedule(static) num_threads(N)`, 行级并行, 无锁 | **~14×** (16t vs 1t) |
| **RGB stride=3** | PIL 内部 RGBA stride=4, 我们 stride=3, 省 25% 内存带宽 | **~1.15×** |
| **float32 权重** | PIL 需独立遍历将 double→INT32 定点数, 我们内联 double→float | **~1.05×** |
| **编译优化** | -O3 对标量循环自动向量化 | **~1.05×** |
| **可变 support 抗锯齿** | support=2.0×max(scale,1.0), 降采样时覆盖更多源像素 | 正确性保证 |
| **中间 clamp** | 水平 pass 输出 round+clamp 到 [0,255], 匹配 Pillow uint8 中间格式 | 消除累积误差 |

### 6.2 Normalize 加速 (1.87ms → 0.07ms, 25.4×)

| 技术点 | 机制 | 收益 |
|--------|------|------|
| **Python→C** | 消除 NumPy 解释器 + 7 个临时数组 (~5MB) | **~20×** |
| **预计算合并常数** | `result = pixel × scale − offset` 替代 `pixel/255 − mean)/std` (3FP→2FP) | **~1.3×** |
| **NEON vld3q_u8** | 一次加载 16 个交错 RGB 像素, 解交错为 R/G/B 三路 | 零额外拷贝 |
| **NEON vcvtq+FMA** | uint8→float32 转换 + vmulq+vsubq 6 通道同时归一化 | 1 次遍历 |
| **OMP 多线程** | 224 行按行并行 | **~3.5×** (4t) |

### 6.3 工程优化

| 技术点 | 说明 |
|--------|------|
| **合并调用** | resize + normalize 在同一个 C++ 函数内完成, 一次 Python↔C 跨越 |
| **预分配输出** | C++ 直接分配 `float32 [6,224,224]`, 省去 torch.from_numpy 的 5-6ms |
| **显式线程控制** | `num_threads` 参数, 生产可调 |
| **编译守卫** | `#if defined(__aarch64__) && !defined(__APPLE__)`, x86/macOS 走标量 fallback |
